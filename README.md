# Hook Management System (HMS)

Version: v3.09

Automated Python pipeline and desktop GUI for syncing AI-generated music stems, transient beat markers, and video shots into DaVinci Resolve using FCP 7 XML interchange.

## Overview

HMS is a production-oriented Python workflow that helps you:

- ingest a master audio track and validate its runtime metadata
- detect the strongest hook window using RMS energy and transient analysis
- rename and sequence render shots naturally and safely
- trim the audio to the exact hook section
- generate a DaVinci Resolve-compatible FCP 7 XML timeline with probed source metadata, linked shot audio, and a separate master-audio lane
- package the app into a Windows desktop executable

This project is designed to keep the repo clean while still supporting a repeatable release pipeline.

## Requirements

- Windows 10 / 11 x64
- Python 3.10+ (recommended 3.11)
- ffprobe installed and available on PATH
- DaVinci Resolve for final import/testing

```powershell

cd hook-management-system

python -m venv .venv
.\.venv\Scripts\Activate.ps1

python -m pip install --upgrade pip setuptools wheel
pip install -r requirements.txt

python hms_master_gui.py
```

## Building the Windows EXE

```powershell
python build_exe.py
```

This generates a Windows executable in the `dist` directory.

## Run history and recovery

The GUI includes a dry-run checkbox, a verify-only action, and controls to roll back the latest run or restore a specific run. Run manifests, rename maps, and overwritten-output backups are stored under `rollback/`.

The command-line utility supports recovery and batch execution:

```powershell
python hms_v31_patcher.py --dry-run --audio "C:\audio\track.wav" --renders "C:\renders" --slug track
python hms_v31_patcher.py --verify-only --slug track --renders "C:\renders"
python hms_v31_patcher.py --rollback
python hms_v31_patcher.py --restore run_003
```

To run the GUI with dry-run enabled, use `python hms_master_gui.py --dry-run`. A normal CLI pipeline run accepts the same `--audio`, `--renders`, and `--slug` arguments without `--dry-run`.

## Build and release automation

The GitHub Actions workflow in `.github/workflows/build.yml`:

- install dependencies
- run the PyInstaller build from `build_exe.py`
- verify the generated EXE
- package the portable build
- upload the archive to a GitHub release when a version tag is pushed
